# Python Compatibility

The authoritative, machine-readable source is
[`compatibility.json`](compatibility.json). It is generated by
`scripts/compatibility_matrix.py` and validated in CI, so it cannot claim
coverage that no differential test actually proves. Regenerate it with:

```bash
python scripts/compatibility_matrix.py --write
python scripts/compatibility_matrix.py --check   # what CI runs
```

## What "supported" means here

A feature is **supported** only when a case in `tests/corpus/` runs the program
under CPython *and* under a compiled native executable, and the two produce the
same stdout, stderr, and exit code. That harness is `benchmarks/difftest.py`.
Nothing here is inferred from the fact that Python parses.

| Status | Meaning |
|---|---|
| `supported` | A differential case proves CPython parity. |
| `partial` | Works for the common shape; the limitation is named per entry. |
| `unsupported` | Rejected with an explicit diagnostic. Never silently wrong. |
| `planned` | Intentionally not started. No claim is made. |

## The limits worth knowing before you write code for Tarvos

These are the ones most likely to surprise, each carried in the matrix with the
same wording.

- **Integers are `i64`, not arbitrary precision.** Python's ints are unbounded;
  Tarvos's are not. Compile-time reductions widen to `u128`, but a runtime value
  cannot exceed `i64`. Large-integer Python programs will not compile.
- **`and` / `or` over non-boolean operands are rejected.** Python returns one
  of its operands (`0 or 7` is `7`); Rust's `||` is boolean. Write
  `bool(x) or bool(y)`.
- **Negative indices work** (Python's `xs[-1]`), and out-of-range raises
  `IndexError` rather than aborting.
- **`list(d)` over a dict is rejected.** A `HashMap` has no insertion order, so
  it cannot reproduce Python's guarantee. Use `sorted(d)`.
- **An empty list needs a type.** `xs = []` then `list(xs)` is rejected until
  something appends to `xs`, because the element type is genuinely unknown.
- **Slice steps are rejected.** `xs[::2]` is not compiled.
- **`import *` is rejected.** The exported name set is not statically known.
- **Relative imports** resolve against the importing module's package; more
  leading dots than directory depth is an error, and a cycle is reported rather
  than mis-inlined.
- **File I/O, `pickle`, `socket`, `asyncio`, and threading are unsupported.**
  No filesystem or network runtime is emitted into generated code.
- **NumPy, Pandas, and PyTorch are not implemented.** There is no adapter and no
  claim of compatibility. They are recorded as future targets only.
- **`pyproject.toml` is not consumed.** It is read by nothing; no dependency
  resolution is attempted. Installing a package does not make it natively
  compilable.
- **There is no `tarvos.toml`.** It was deliberately not introduced.
